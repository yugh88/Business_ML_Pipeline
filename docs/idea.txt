### The Fundamental Mathematical Hurdle

In Macro $F_{0.5}$, Precision is weighted 4× heavier than Recall:
$$F_{0.5} = \frac{5 \cdot P \cdot R}{P + 4R}$$

To achieve **$F_{0.5} \ge 0.9940$**, your system must operate at:
* **Precision $\ge 99.65\%$** (Fewer than 1 false positive per 300 queries).
* **Recall $\ge 98.40\%$**.

Standard pipelines (BM25 + TF-IDF blocking + LightGBM pairwise features) top out at 0.978 because **string edit distances treat adversarial twin distractors identically to harmless typos**:
* Typo: `Main St` vs `Main Saint` (Edit distance = 3) $\rightarrow$ **True Match**
* Distractor: `20 Rue Parmentier` vs `22 Rue Parmentier` (Edit distance = 1) $\rightarrow$ **False Match (Destroys Precision)**

### Pillar 1: Adversarial Twin Mining Curriculum (Data Synthesis)

The primary reason LightGBM models fail on test distractors is that **the training set does not expose them to enough hard negatives**.
Standard negative sampling (BM25 top-k) mostly returns different businesses with similar names. Amazon's benchmark generator explicitly constructed synthetic hard negatives by:
1. Shifting house numbers by $\pm 1, \pm 2, \pm 5, \pm 21$.
2. Swapping sub-plots (`42/2/3` $\rightarrow$ `42/2/7`).
3. Retaining business names while shifting to an adjacent street in the same city.

**The Solution:**
* Re-implement Amazon's generative distractor engine on the training data.
* For every true training pair $(S_1, T)$, generate **5 synthetic adversarial twins**:
  * Numerical shift: perturb door/plot numbers while keeping street/city identical.
  * Street shift: keep house number and city, change street to another in the same locality.
* Train models on a **triplet / contrastive loss** where the margin between the true match and the synthetic twin is explicitly maximized.

### Pillar 2: Token-Level Cross-Encoder (DeBERTa-v3-large / ModernBERT)

Pairwise tabular features compress names and addresses into scalar numbers (e.g., Jaro-Winkler = 0.94). A scalar feature cannot distinguish *which* token differed.

**The Solution:**
Feed pairs directly into a Cross-Encoder with full cross-attention:
$$\text{[CLS]} \quad \text{Name}_1 \parallel \text{Address}_1 \quad \text{[SEP]} \quad \text{Name}_2 \parallel \text{Address}_2 \quad \text{[SEP]}$$

* **Why Cross-Attention breaks the 0.98 barrier:**
  * When self-attention heads compute attention across the separator, the query token `20` directly attends to `22`.
  * The transformer learns that when entity name and street attend with 99% similarity, a mismatch on the isolated door number token is an **immediate veto**, suppressing the output probability below the singleton threshold.
* **Pre-training:** Continual domain pre-training (Masked Language Modeling) on OpenStreetMap (OSM) address nodes and French Sirene/INPI corporate registry data.

### Pillar 3: Semantic Number Parsing & The Numerical Disentanglement Layer

Instead of treating digits as strings, build an explicit **Address Grammar Parser**:
1. **Token Typing:** Tag numbers using a sequence tagger (CRF or fine-tuned DistilBERT) into:
   * `[DOOR_NUM]` (e.g., `20`, `14028`)
   * `[SUB_UNIT]` (e.g., `Flat 401`, `Shop 4`, `37B`)
   * `[PLOT_NUM]` (e.g., `42/2/3`)
   * `[POSTAL_CODE]` (e.g., `59000`, `400058`)
2. **Deterministic Veto Graph:**
   $$\text{If } \text{Type}(n_1) = \text{Type}(n_2) = \text{[DOOR\_NUM]} \text{ and } 1 \le |n_1 - n_2| \le 50 \implies \mathbf{Score} = 0.000$$
   This single rule mathematically immunizes the system from all $+1/+2$ synthetic twin distractors across all countries.

### Pillar 4: Dedicated Singleton Gate ($P(\text{Singleton})$)

5.58% of entities in the benchmark have **zero true matches**.
In standard pipelines, a query with zero true matches is matched against its highest-scoring candidate. If that candidate scores 0.66 (just above a 0.65 threshold), you incur a catastrophic **$-1.000$** penalty on that query's Macro $F_{0.5}$.

**The Solution:**
Train a separate binary classifier:
$$f_{\text{singleton}}(S_1) \rightarrow P(S_1 \text{ has no duplicate anywhere in } S_2/S_3)$$
* **Features for Singleton Gate:**
  * Entropy of top-$k$ candidate retrieval scores.
  * Score gap between rank 1 and rank 2 candidates.
  * Entity name rarity in global corpus (TF-IDF sum).
* If $P(\text{singleton}) > \tau_{\text{singleton}}$, predict an empty set `[]` immediately, bypassing candidate matching entirely. This protects the 5.6% singleton pool with near 100% precision.

### Pillar 5: Global Bipartite Maximum Weight Matching (Min-Cost Max-Flow)

Standard entity resolution greedily assigns targets based on independent pair scores.
In real data, each target entity $T \in S_2 \cup S_3$ can belong to **at most one** $S_1$ entity (unless it is a confirmed enterprise chain).

**The Solution:**
Formulate final prediction as a **Global Linear Sum Assignment Problem (LAP)**:
$$\max \sum_{i \in S_1} \sum_{j \in S_2 \cup S_3} W_{ij} X_{ij}$$
$$\text{subject to: } \sum_{i} X_{ij} \le 1 \quad \forall j, \quad X_{ij} \in \{0, 1\}$$
Where edge weight $W_{ij} = \log\left(\frac{P_{ij}}{1 - P_{ij}}\right) - \lambda_{\text{threshold}}$.

Solving this with the **Jonker-Volgenant algorithm** or **Min-Cost Max-Flow** eliminates 100% of duplicate target contention globally and optimizes the entire 1.73M dataset assignment simultaneously.
